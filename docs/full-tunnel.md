# Client02: full tunnel

В конфигурации `client02` указано:

```text
AllowedIPs = 0.0.0.0/0
```

`wg-quick` создаёт отдельную таблицу маршрутизации и `ip rule`, чтобы не
зациклить UDP-пакеты к endpoint. Проверка:

```text
ip route get 8.8.8.8 -> dev wg0 table 51820 src 10.50.0.3
traceroute 8.8.8.8  -> 10.50.0.1, затем 192.168.239.2
ping 8.8.8.8        -> успешно
```

Первый hop `10.50.0.1` доказывает, что трафик сначала попадает на VPN-сервер,
а NAT на `vpn-server` выпускает его в WAN.

В VM-лаборатории клиенты и VPN-сервер подключены к одному VMware NAT, поэтому
публичный IP через `curl` совпадает даже при split tunnel. Для full tunnel
надёжным доказательством являются `ip rule`, маршрут через `wg0`, traceroute и
счётчик NAT на VPN-сервере.
